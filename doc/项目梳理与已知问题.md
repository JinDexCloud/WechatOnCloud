# 项目梳理与已知问题

> 本文记录当前版本的模块边界、运行链路、应用类型和已知问题，作为维护入口。部署步骤与日常命令见[部署与运维](部署与运维.md)，设计背景见[技术方案](技术方案.md)。

## 1. 项目定位

WechatOnCloud（云微）是一个基于 Docker 的远程桌面应用平台。每个实例运行在独立容器中，通过 KasmVNC 将容器桌面转成浏览器可访问的页面；面板负责登录鉴权、实例生命周期、访问权限和 VNC 反向代理。

当前支持的应用类型：

| 类型 | 启动方式 | 数据持久化 | 备注 |
|---|---|---|---|
| 微信 | 数据卷内运行时下载安装 | `/config` | 首次使用需管理员触发安装并扫码 |
| Telegram | 数据卷内安装/启动 | `/config` | 运行时安装 |
| Chromium | 镜像内 `/usr/bin/chromium` | `/config/chromium` | 创建后即可进入 |
| Edge | amd64 镜像内 `/usr/bin/microsoft-edge`；arm64 回退 Chromium | `/config/edge` | 创建后即可进入 |
| 自定义 | 数据卷内命令 | `/config` | 需管理员配置启动命令 |

## 2. 目录与职责

- `docker/`：实例镜像、桌面启动脚本、应用定义、微信下载控制和 noVNC 中文输入补丁。
- `panel/server/`：Fastify 服务端；账号、实例、权限、Docker API、反向代理和 watchdog。
- `panel/web/`：React + TypeScript 管理面板与桌面页。
- `fnos/`：飞牛 NAS 应用打包工程。
- `doc/`：部署、运行原理、技术方案、数据卷、安全和发布文档。
- `.github/workflows/`：多架构镜像构建、发布和发布前探针。
- `docker-compose.yml`：默认部署入口；宿主只暴露面板端口，实例由面板按需创建。

## 3. 启动链路

1. `docker compose` 启动 `woc-panel`，面板挂载 `docker.sock`。
2. 管理员在面板创建实例，服务端校验 `appType`，创建容器、命名卷和访问权限。
3. 容器启动钩子写入实例应用类型；Openbox 会话执行 `docker/autostart`。
4. `autostart` 从 `app-defs.sh` 获取可执行文件和启动命令，等待应用就绪后常驻拉起；应用退出会自动重启。
5. 用户访问 `/desktop/:id/`，面板校验权限并反代到实例 KasmVNC，浏览器不直接接触 VNC 凭据。

## 4. 本次已修复：Edge 无法运行

### 根因

Edge 曾配置为：

```sh
APP_BIN="/usr/bin/microsoft-edge"
```

但 `autostart` 通过 `[ -x "$APP_BIN" ]` 判断应用是否已安装。相对命令名不会按 `PATH` 解析，脚本因此永久停留在“尚未安装”等待循环。另外，服务端 `APP_TYPES` 白名单漏掉 `edge`，面板创建请求会回退为微信。

### 修复

- 服务端白名单加入 `edge`，创建的实例不再被回退为微信。
- `APP_BIN` 改为 `/usr/bin/microsoft-edge`，与可执行文件检测逻辑一致。
- 启动命令使用 `--profile /config/edge`，Edge 配置、Cookie 和登录态写入实例数据卷。
- 容器启动钩子会预创建 `/config/edge` 并交给桌面用户，避免空数据卷首次启动出现 `Profile Missing`。
- Microsoft Edge 官方 Linux 包目前仅提供 amd64；arm64 构建保留 Edge 应用类型，但实际使用固定版本 Chromium 兼容回退。
- 保留 `--no-remote --new-instance`，避免复用其他 Edge 进程或 profile 锁。

### 验证标准

重建实例镜像和面板后，新建 Edge 实例，进入桌面应能看到 Edge 窗口；容器日志应出现：

```text
[autostart] 启动 Edge: /usr/bin/microsoft-edge ... --user-data-dir=/config/edge
```

可用以下命令辅助检查：

```bash
docker logs woc-wx-<id>
docker exec woc-wx-<id> sh -lc 'test -x /usr/bin/microsoft-edge && echo edge-ready'
```

旧的 Edge 实例若是在修复前创建的，建议在面板重启实例；若其 `appType` 已被旧服务端保存为 `wechat`，需新建 Edge 实例，或在数据层谨慎修正后再启动。

## 5. 当前已知问题与限制

- 面板依赖宿主 Docker daemon 和 `docker.sock`；该权限接近宿主 root，必须只对可信管理员开放。
- 远程桌面依赖 WebSocket；使用 Nginx、Cloudflare 或其他反代时，需要透传升级头并提高空闲超时。
- 局域网 HTTP 下，浏览器可能禁用麦克风/摄像头和系统剪贴板；可使用面板内置文本剪贴板转发。媒体权限建议使用 HTTPS。
- 实例是完整远程桌面，多人同时操作会互相影响；面板提供软锁，但不替代协作约定。
- Chromium/KasmVNC 在无客户端连接的退化分辨率场景对版本敏感，镜像已固定 Chromium 版本；升级必须通过发布门禁中的探针。
- 实例内存主要受 KasmVNC、Chromium 内核和标签页数量影响；watchdog 可用于异常内存增长自愈，但重启会中断当前桌面会话。
- 微信本体不随镜像发布，首次安装依赖腾讯 CDN；下载失败时可重试或配置可达的镜像源。
- 微信登录态可能因客户端或风控策略失效，需要手机重新扫码；设备伪装配置只能降低部分重复设备风险。

## 6. 修改后的验证清单

```bash
# Shell 语法
bash -n docker/app-defs.sh docker/autostart docker/woc-app-init.sh

# 面板服务端类型检查与构建
cd panel/server && npx tsc --noEmit

# 前端构建
cd ../web && npm run build
```

完整容器级验证还需要在目标架构上构建镜像，并按[发布门禁](dev/发布门禁.md)执行 Chromium、微信运行时和 KasmVNC 探针；Edge 的人工验收重点是“创建类型不回退、窗口启动、用户数据写入 `/config/edge`、重启后登录态保留”。 发布探针使用与桌面会话相同的 UID 1000；以 root 调用 Edge 可能因 Edge 的 root 运行限制而误报失败。
